# from-ux-to-insights

From UX to Insights is my journey from understanding people and designing experiences to uncovering the patterns behind their behaviour. I'm building my skills in SQL, product analytics and data visualisation, one project at a time, with the goal of turning data into meaningful insights and better product decisions.

# Product Analyst Learning Roadmap

A 12-week, self-directed learning plan for transitioning into Product Analytics, while keeping general Data Analyst opportunities open.

## Profile and goal

This roadmap is designed for someone with:
- 10 years of UX design experience
- A degree in Psychology, including Research Methodology
- Enterprise software support experience
- Familiarity with HTML, CSS, JavaScript, React and product/support tools

**Career direction:** UX-informed Product Analyst, with transferable skills for Data Analyst and Product Insights Analyst roles.

## How to use this repository

1. Create a GitHub repository for this roadmap.
2. Upload this folder's contents.
3. Create a GitHub Project and import `roadmap/github-project-import.csv` (or add the tasks manually if your Project view does not offer CSV import).
4. Track progress by moving each weekly item through your Project's status columns.
5. Keep notes, SQL queries, dashboards and case studies in the relevant folders.
6. Use the weekly checklist below as a simple progress view.

Suggested Project status options: **Todo**, **In progress**, **Blocked**, **Done**.

Suggested labels: `foundations`, `sql`, `product-metrics`, `statistics`, `visualisation`, `experimentation`, `portfolio`, `career`.

## Suggested weekly time commitment

Aim for 6–8 hours per week:
- Reading and theory: 1 hour
- Lessons: 2 hours
- SQL / practical exercises: 2 hours
- Portfolio work: 2 hours
- Review and notes: 1 hour

The 12 weeks are a guide, not a deadline. Spend longer on SQL or statistics if needed.

## 12-week overview

| Week | Focus | Main deliverable |
|---|---|---|
| 1 | Understand the Product Analyst role | Create a one-page role and terminology reference sheet. Write five product questions you would investigate for a fictional SaaS product. |
| 2 | Product metrics and measurement | Create a Product Metrics Dictionary with definitions, calculation logic, business relevance and possible actions. |
| 3 | SQL fundamentals | Complete beginner SQL lessons and save at least 15 working queries in your repository. |
| 4 | Intermediate SQL | Write 10–15 queries joining customer, subscription and activity data. Explain what each query answers. |
| 5 | Funnels and cohorts | Produce a funnel and cohort analysis. Identify a drop-off point, compare cohorts and suggest UX hypotheses. |
| 6 | Statistics for Product Analysts | Write a short report interpreting an observed relationship, explaining limitations and what further evidence is needed. |
| 7 | Data visualisation and Power BI | Build a dashboard showing users, activation, retention, feature adoption and conversion. Include a short interpretation. |
| 8 | A/B testing and experimentation | Create an A/B test case study for a simplified onboarding flow. State the hypothesis, metrics, analysis and recommendation. |
| 9 | Product analytics and event tracking | Create an event-tracking specification for a fictional SaaS product, including events, properties and the questions each event supports. |
| 10 | Portfolio project: onboarding analysis | Publish a case study with business problem, data, SQL, funnel findings, visualisations, UX recommendations and measurement plan. |
| 11 | Portfolio project: retention analysis | Publish a case study with SQL, cohort analysis, retention charts, dashboard and evidence-based recommendations. |
| 12 | Portfolio project: experimentation and career prep | Publish the A/B testing case study; update CV and LinkedIn; identify 20 target employers and begin applying to suitable roles. |

## Important data and portfolio hygiene

- Use public or synthetic datasets only.
- Do not upload employer data, customer information, screenshots of internal systems, credentials or confidential documentation.
- Explain assumptions, metric definitions and data limitations.
- A good case study explains the business question and recommendation, not just the charts or SQL.
